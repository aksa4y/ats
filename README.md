# ATSExhaust — дым выхлопа для ATS / Windows / SPF

Windows-контроллер частиц реализован для **ATS 1.61.3.18** из предоставленного `amtrucks.exe`.
Он регулирует число дымовых частиц по газу, оборотам и нагрузке двигателя.
При выключенном двигателе контроллер прекращает создание распознанных частиц дыма.
Уже созданные частицы исчезают по истечении их времени жизни.

**Версия экспериментальная. Сборка и автоматические тесты не заменяют проверку внутри ATS.**
Работа эффекта в запущенной игре пока не подтверждена.
Поддержка ограничена точным SHA-256, а не только номером версии игры.

## Установка

1. Скачайте [ZIP исходников](https://github.com/aksa4y/ats/archive/refs/heads/main.zip).
2. Распакуйте архив в постоянную папку.
3. Закройте ATS.
4. Запустите `run.bat`.
5. Если Windows запросит права для установки VC++ Runtime, разрешите установку.
6. В менеджере модов ATS включите companion-мод дыма.
7. Для первого теста используйте копию игрового профиля и штатный поддерживаемый грузовик.
8. В интерфейсе SPF откройте окно ATSExhaust.

Companion сохраняется в `Документы/American Truck Simulator/mod/ATSExhaust_Companion.scs`.
В менеджере модов отображается имя из оригинального манифеста, **PM 389 Smoke**.
Скрипт не изменяет список активных модов в игровом профиле.
Если другая копия этого smoke-мода уже активна, выключите дубликат.

`run.bat` устанавливает SPF, нашу DLL и companion-мод с моделями выхлопа.
Companion скачивается из указанного пользователем исходного репозитория по закреплённой ревизии.
Его SHA-256 проверяется перед установкой. Копия архива в этом репозитории не публикуется.
Пакет не содержит оригинальный MODGuard.dll и не обходит его активацию.

Существующие `ATSDamage` и другие SPF-плагины сохраняются.
Одновременно использовать оригинальный MODGuard.dll и ATSExhaust не следует: оба управляют дымом.
При обнаружении MODGuard.dll установщик остановится с объяснением.

## Команды

| Файл | Действие |
| --- | --- |
| `run.bat` | Скачать релиз, установить зависимости и companion, затем запустить ATS. |
| `update.bat` | Обновить наш модуль, SPF и companion без запуска игры. |
| `diagnose.bat` | Записать путь, версию и SHA-256 игры без установки. |
| `build.bat` | Собрать DLL из исходников и выполнить тесты. |

Если автоматический поиск не выбрал нужную библиотеку Steam:

```bat
run.bat -GamePath "D:\SteamLibrary\steamapps\common\American Truck Simulator"
```

Если ATS использует нестандартный каталог профиля через `-homedir`:

```bat
run.bat -ProfileDirectory "D:\ATS Profile" -NoLaunch
```

`-ProfileDirectory` выбирает место установки companion. Аргумент не меняет команду запуска игры.
При нестандартном `-homedir` запускайте ATS своим настроенным ярлыком после установки с `-NoLaunch`.

Если совместимый companion уже установлен под другим именем:

```bat
run.bat -SkipSmokeMod
```

Для установки без запуска игры добавьте `-NoLaunch`.
Для командного запуска без паузы задайте `ATS_NO_PAUSE=1`.
Требуются Windows 10/11 x64, Windows PowerShell 5.1 и доступ к GitHub и Microsoft.

## Проверка дыма

В окне ATSExhaust должны появиться:

- Статус «Перехват частиц активен: ATS 1.61.3.18».
- Статус «Телеметрия поступает» после начала поездки.
- Растущие счётчики распознанных, пропущенных и подавленных частиц.

Во внешней камере сравните выключенный двигатель, холостой ход и разгон под нагрузкой.
При выключении двигателя новые частицы прекращаются. Старые частицы могут оставаться ещё несколько секунд.
При увеличении нагрузки полоса интенсивности и доля пропущенных частиц должны увеличиваться.

Если счётчик частиц равен нулю, проверьте активность companion и совместимость выбранной модели выхлопа.
Одна DLL не добавляет точки выхода дыма на произвольный грузовик.
Заменяющие модели грузовиков и выхлопных труб моды могут перекрывать companion.
Поддерживаются три исходных слоя дыма. Пресет `dynamic-blend` не поддерживается.

Для сообщения об ошибке приложите скриншот окна ATSExhaust, `.state/diagnostics.json` и журнал SPF.
Отчёт диагностики остаётся на вашем компьютере и содержит локальный путь установки.

## Совместимость и обновления игры

Поддерживаемый SHA-256:

```text
c60e8ee02cc97b3cc6ef8c6298bb5c3c23c4ffd330b8185b646fb1b608a3c7b4
```

Установщик и DLL независимо проверяют этот хеш.
Перед подключением перехвата DLL также проверяет байты функции, таблицу методов и проверку результата выделения памяти.
Нераспознанные генераторы и другие вызовы allocator продолжают работать через исходную функцию.

`update.bat` получает опубликованные исправления. Он не создаёт поддержку неизвестных версий 1.63/1.64.
После изменения игры потребуется исследование новой сборки и выпуск нового профиля.
При неизвестном хеше перехват отключается. Сам companion тогда может давать постоянный дым — выключите его до совместимого релиза.

Все заменяемые файлы получают резервные копии в `.state/backups`.
При ошибке копирования скрипт восстанавливает затронутые файлы.
Настройки SPF, соседние плагины и игровые сохранения не перезаписываются.

## Build and evidence

The Windows backend requires MSVC x64. CMake builds the DLL with a static C++ runtime.
GitHub Actions runs C++ tests on Windows and Linux.
Installer tests also run under Windows PowerShell 5.1 and PowerShell 7.

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --config Release --parallel
ctest --test-dir build -C Release --output-on-failure
pwsh -NoProfile -File tests/installer_test.ps1
```

The Linux build tests the portable logic. It is not a Linux game plugin.
The companion archive and the game executable are not included in test fixtures.

[Static evidence](compatibility/windows-1.61.3.18.md) records the ABI, offsets, call site, and validation limits.
`research/verify_windows_profile.py` checks this evidence against a local executable with `pefile`.
See [THIRD_PARTY.md](THIRD_PARTY.md) for source attribution.
